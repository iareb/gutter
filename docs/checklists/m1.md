# M1 checklist — Basic viewer

Run on the built app before closing M1, on each platform. Mark each cell **ok** or the number of the issue opened for it. A failure becomes an issue with the bug report form: steps, expected, actual, platform, version.

**Setup.** Generate the test files with `pnpm corpus`; on Android copy them to `Download` with `adb push`. Desktop: build with `pnpm tauri build --no-bundle` and start `src-tauri/target/release/gutter` (`gutter.exe` on Windows). Android: `pnpm tauri android dev` (a signed release build comes with M5). Files are in `corpus/generated/`.

Android only: after picking a file, and after switching to another app and back, the open page must still be there.

"Automated" means the action was run by a script on the release app, with real key events, checking which page was actually drawn; only the system file picker was bypassed.

Known limits, not failures: no zoom or gestures (M2), no double page, vertical scroll or right-to-left reading (M3), no preloading (M3), no library (M4), CBZ only (CBR in M5).
