# M4 checklist — Library

Run on the built app on each platform. Mark each cell **ok**, **—** (not applicable or not run) or the number of the issue opened for it. A failure becomes an issue with the bug report form and a test that would have caught it.

**Setup.** Generate the volumes with `pnpm corpus`. Desktop: build with `pnpm tauri build --no-bundle` and start `src-tauri/target/release/gutter` (`gutter.exe` on Windows). Android: build and install the debug APK, `pnpm tauri android build --debug --apk --target aarch64` then `adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`, and copy a few comics into a folder inside `Download` (not `Download` itself: Android does not let an app pick it). The library lives in `library.sqlite3` in the app's data folder (`%APPDATA%\io.github.iareb.gutter` on Windows, `~/.local/share/io.github.iareb.gutter` on Linux, the app's private folder on Android) and the covers in its cache folder: moving them aside starts from an empty library.

For a library of 40 volumes, the scratch scripts made 40 distinct CBZ files from the corpus, each with a different ZIP comment so that each has its own fingerprint.

**Failures found while writing M4, and their tests.**

- A folder holding two copies of one comic moved the volume back and forth between them each time it was listed (step 4.2, on the phone). A copy of a volume whose file still opens is now left out: `library::tests::a_copy_of_a_volume_still_there_adds_nothing`.
- Find it… in the dialog of a missing volume did nothing: the dialog closed before handing on its volume (step 4.7, on Windows). The dialog now takes the volume before it closes, in one function the buttons share (`settle` in `Library.svelte`). The repository has no test of Svelte components yet: the end-to-end check of item 30 is what found it, and it is the one to run.
