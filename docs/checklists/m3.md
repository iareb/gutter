# M3 checklist — Reading modes

Run on the built app on each platform. Mark each cell **ok**, **—** (not applicable or not run) or the number of the issue opened for it. A failure becomes an issue with the bug report form and, when it is a gesture, a recording added to `tests/recordings/` with a test that replays it. This file holds the items of steps 3.1 to 3.3 (page cost, cache, preloading); the items of the other steps are added as they are written.

**Setup.** Generate the volumes with `pnpm corpus`. Desktop: build with `pnpm tauri build --no-bundle` and start `src-tauri/target/release/gutter` (`gutter.exe` on Windows). Android: build and install the debug APK, `pnpm tauri android build --debug --apk --target aarch64` then `adb install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`, and copy `basic.cbz` and `large.cbz` to `Download` with `adb push`. A release build has no overlay unless the page's `localStorage` has `gutter.stats` set to `1` (reload after setting it); a development build always has it. The overlay shows the cache against its budget, the bitmaps alive, the last fetch and decode times, and how long the last page change took and whether the page was ready.

"Automated" means the action was sent by a script and the result read from the page (and from the overlay), as in the earlier checklists: on Windows with real wheel, key and mouse events through the webview's DevTools protocol (the release build); on the phone with taps and swipes sent by `adb shell input` and the file chosen in the system picker; "WSL" is WebKitGTK in WSL with DOM events (the development build). The M2, M2.5 and M2.6 checklists were run again on Windows after the viewer was rewritten around the page store: all pass. On the phone the slider items of the M2.6 checklist pass again (page 40 of `large-solid.cbr` 2.3 s after the finger left, only that page fetched), and the touch items of the M2 checklist pass, except those that expect the old hiding header and the fit size measured without the options bar.

Known limits, not failures: on a solid archive a far jump or fast flipping waits for the pass over the archive; on the phone a page that is not ready (the first after opening, a jump, flipping faster than the preloading) takes about 0.7 s, against 0.1 s before M3: every page is now made in main memory, which keeps the graphics memory flat; a huge page at the highest zoom keeps graphics memory after it is shown (see the spike).
