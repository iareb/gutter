# M2 checklist — Gesture engine

Run on the built app before closing M2, on each platform. Mark each cell **ok**, **—** (not applicable or no hardware) or the number of the issue opened for it. A failure becomes an issue with the bug report form, and, when it is a gesture, a recording added to `tests/recordings/` with a test that replays it (the "● Rec" button of a development build saves one).

**Setup.** Generate the test files with `pnpm corpus`; on Android copy them to `Download` with `adb push`. Desktop: build with `pnpm tauri build --no-bundle` and start `src-tauri/target/release/gutter` (`gutter.exe` on Windows). Android: `pnpm tauri android dev`. Files are in `corpus/generated/`. Each page of `basic.cbz` shows its own number large, so you can check the page without the header.

**Devices.** Windows: mouse and keyboard (no trackpad). Linux: the laptop, with its trackpad and keyboard. Android: touch only, with the phone upright.

**How each cell was run.** The agent ran everything it could on 2026-11-10, with these differences (items 1 and 2 were redone after the options bar became permanent):

- **OK (automated), Windows:** the release build, with real mouse, wheel and key events sent through the webview's DevTools protocol; only the file picker's answer was replaced. The result was read from the page (page number, canvas size and pixels).
- **OK (emulated touch), Windows:** this PC has no touch screen, so touches were sent as emulated DevTools touch events, 50 swipes included. It checks the engine, not a finger on glass.
- **OK (automated), Android:** the phone upright and `basic.cbz` already open (the file picker cannot be driven). Taps and swipes are real touches sent with `adb shell input` (the 50 swipes among them); double tap and pinch are DevTools touch events, because `adb` cannot send two fingers. Rotation was changed with the system settings and put back.
- **OK (WSL), Linux:** WebKitGTK in WSL, with DOM events sent from inside the page, not real input.
- **Still to do by hand:** the Linux column on the laptop (real mouse, keyboard and above all the trackpad, items 20 to 24; the Linux cells above only show that the same checks pass in WSL) and a look with your own eyes at sharpness after zooming and rotating.

What the run found: a fast mouse wheel spin (notches under 40 ms apart) turned only one page after step 2.6 (fixed: the same big step again counts as a notch); every other failure was a mistake in the test script, not in the app.

Known limits, not failures: the next page appears once decoded, not sliding in (preloading comes in M3); no vertical scroll, double page or right-to-left reading (M3); CBZ only (CBR in M2.5); trackpad pinch on **Windows** is untested, there is no trackpad there: it should arrive as Ctrl+wheel in small steps; settings for the thresholds come later.
