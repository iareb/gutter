# Spike S3 — Android file access

**Question:** does the app run on a real Android phone and open a file picked with the system picker?

**Answer: yes.** Rust opens the `content://` URI returned by the picker as a seekable file and reads a single page from a CBZ without loading the archive. From picking the file to the page on screen: **102 ms**, in a debug build.

Date: 2026-10-31 · Code: branch `spike/s3` (not merged)

## Setup

| | |
| --- | --- |
| Device | Motorola Edge 60, Android 16, Android System WebView 156 |
| Connection | Wireless debugging (`adb pair` + `adb connect`) |
| Build | `pnpm tauri android dev`, Rust debug profile (unoptimized) |
| Test file | Synthetic CBZ, 50.2 MB, 21 entries (20 JPEG pages of 1988 × 3056 + one text file sorted first), stored without compression, copied to `Download` with `adb push` |

## What the spike does

1. `open()` from `@tauri-apps/plugin-dialog` shows the system picker and returns a URI.
2. The URI is passed to two Rust commands. Both open it with `app.fs().open()` from `tauri-plugin-fs`, which turns a `content://` URI into a `std::fs::File`, then read it with the `zip` crate.
   - `inspect_archive` reads only the ZIP index and lists the image entries.
   - `read_first_page` extracts only the first image and returns its raw bytes through `tauri::ipc::Response` (no JSON encoding).
3. The webview wraps the bytes in a `Blob`, decodes them with `img.decode()` and shows the page.

## Results

| Step | Time |
| --- | --- |
| Picker (includes the user's choice) | 971 ms |
| Rust: open the `content://` file | 14.0 ms |
| Rust: read the ZIP index (21 entries) | 0.2 ms |
| Rust: extract page 1 (2.6 MB) and send it to the webview | 43.5 ms |
| WebView: decode the JPEG (1988 × 3056) | 57.5 ms |
| **Total from choice to page on screen** | **101.6 ms** |

URI returned: `content://com.android.providers.downloads.documents/document/msf%3A1000171430`

## Findings

- **`content://` works from Rust.** No storage permission is needed: the picker grants read access to the chosen file. The file is seekable, so the ZIP index is read without scanning the archive: the design's core assumption holds on Android.
- **A file copied with `adb push` is visible in the picker** under Download even though the Files app search does not find it (it was never added to the media catalog).
- **Non-image entries are skipped** correctly (`00_readme.txt` sorted first).

## Caveats

- Debug build: release Rust will be faster. The numbers are an upper bound for this device.
- 50 MB file, not the 100 MB of the design target. Opening and reading the index do not depend on file size, so we expect the same order of magnitude.
- Pages travel via IPC (`ipc::Response`), not via the custom protocol the design calls for. That comparison is S1's job.
- Decoding used `img.decode()`, not `createImageBitmap` with resize. That is S2's job.

## Issues found along the way

- **Vite reloads the page after the picker.** While the picker is open the app is in the background, Android drops the dev server connection, and Vite reloads the page when it reconnects, losing state. Development only; it happened once in two runs. Possible fix: disable HMR when running on Android.
- **Huge dev APK.** Full debug info made it 304 MB (157 MB Rust library), about 3 minutes to install over Wi-Fi. With `debug = "line-tables-only"` for our crate and no debug info for dependencies: 147 MB APK, 36 MB library. Still worth investigating what else is in the APK.
- **Native abort on app exit**, seen once: `FORTIFY: pthread_mutex_lock called on a destroyed mutex`, followed by the GPU driver unloading. It happens while the process shuts down, not during use. To keep an eye on.
- **The dev build does not work on its own.** Launched from the home screen without `tauri android dev` running, it closes after about 1.5 s because it cannot reach the dev server. Expected; a standalone build needs `tauri android build`.

## Decision

No change to the design. Android file access through the system picker and `tauri-plugin-fs` is confirmed as the way to open files on mobile.
